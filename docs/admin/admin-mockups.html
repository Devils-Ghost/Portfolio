Foundations

The scales every screen below is built from. Revision 1 had roughly fifteen distinct font sizes and off-grid padding values (17px, 13px, 9px, 2.5px); that is the clearest tell of a design assembled by eye rather than from a system. Seven type steps and a 4pt spacing grid replace them.

Colour — measured, not eyeballed

Revision 1's two metadata greys failed WCAG AA on this background: #6b7280 at 3.97:1 and #4b5563 at 2.54:1, both carrying dates, counts, IDs and keyboard hints. In an admin panel the metadata is the content, so they are merged into one tertiary that clears 4.5:1.

02

Heavy-entity editor

URL-driven so refresh and Back behave, with Escape and backdrop click guarded when the draft is dirty. Width corrected: revision 1 specified a 900px modal and a rule that split view collapses below 1100px because two ~400px panes are worse than one — but a 900px modal minus a 164px rail yields two ~350px panes on every screen, so split could never have been valid. Entities with a long-form body now open at 1140px, everything else at 800px, and split is gated on the editor pane measuring ≥720px rather than on the viewport.

03

Featured manager

Ordered by home page section, not by entity type, so the page reads as a schematic of the home page top to bottom. Sections that can't be feature-managed stay as dimmed position markers. Press and hold a drag row below — it lifts and shadows on grab, which is what tells you the row was picked up rather than clicked. Every row also carries move up / move down / unfeature buttons: WCAG 2.2 SC 2.5.7 requires a single-pointer path for any drag operation, and a keyboard alternative does not satisfy it — someone using a head pointer or switch has a pointer but cannot drag.

06

Year and month scroller

Every dated entity stores month precision only, so a native date input is the wrong control: it asks for a day you will never show and renders differently in every browser. Years scroll in a snap column, months sit in a fixed grid, so any date is two clicks. The end tab carries a Present switch, which writes null and greys the columns. The trigger renders through the same formatDateRange() the public site uses, so what you see here is what ships.

07

Skill picker

Clicking add skill opens a floating command menu rather than expanding a list in place. Results group by category, and the search matches aliases as well as names, reusing the same match function the public about page will need for its skill matrix. The menu stays open after a toggle so several can be added in one pass. The usage count is what stops near-duplicate skills accumulating: a skill nothing references is flagged, because that is a pill that would open an empty modal on the live site.

08

The states nobody mocks up

Revision 1 specified empty-state and error copy in prose but drew none of them, and drew no loading or destructive-confirm state at all. These are where an admin panel actually spends a meaningful share of its time, and they are the states most likely to end up improvised during the build. The failed-save state is the one a section rail makes uniquely necessary — see §02, where the rail carries the error marker.
